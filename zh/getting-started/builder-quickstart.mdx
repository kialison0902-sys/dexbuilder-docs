<Warning>
  本页所有 Builder 操作都是待开发目标。所列路径是 Orderly 参考路径，不是可调用的 DexBuilder 接口。
</Warning>

这是 DexBuilder 应支持的最小 Builder 流程，不额外虚构 Project、Webhook、Payout 或通用交易构造 API。

<Steps>
  <Step title="◇ 建立 Builder 身份">
    通过管理端 Onboarding 创建 Builder 资料并取得 Builder 标识，不假设存在单独的 `project_id` API 资源。
  </Step>
  <Step title="◇ 注册用户">
    按 Orderly 模式读取 `GET /v1/registration_nonce`，取得钱包签名，再通过 `POST /v1/register_account` 提交并记录 Builder 归属。
  </Step>
  <Step title="◇ 创建用户交易凭证">
    为用户添加可撤销的交易凭证，对应 Orderly 的 `POST /v1/orderly_key` 流程；Builder 管理权限只放在服务端。
  </Step>
  <Step title="◇ 通过 Vault 充值">
    使用当前环境的抵押资产和 Vault 合约：先 `approve`，读取 `getDepositFee`，再调用 `deposit`，最后通过资产历史确认入账。
  </Step>
  <Step title="使用现有交易 API">
    通过已发布的交易 API 接入行情、订单、仓位、成交、账户数据和交易费率。
  </Step>
  <Step title="◇ 结算或转移资金">
    为提现、PnL 结算及内部划转实现与 Orderly 一致的 Nonce 加签名请求流程。
  </Step>
  <Step title="◇ 配置手续费并核对收入">
    实现 Builder 默认费率、用户级费率、每日交易量、Builder 信息和每日手续费收入查询。
  </Step>
</Steps>

## 核心标识

| 标识 | 用途 |
|---|---|
| `builder_id` | DexBuilder 对 Builder 归属的产品命名；最终线上字段名仍需开发确认 |
| `account_id` | 已注册的用户交易账户 |
| 钱包地址 | 用户控制的身份，用于注册及钱包授权操作 |
| 交易凭证 | 可撤销的用户认证交易凭证 |

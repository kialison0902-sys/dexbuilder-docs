---

HTTP 成功响应表示请求已被接受处理，并不一定表示订单已经成交。

`text
SUBMITTED → ACCEPTED → OPEN ───────────────→ FILLED
                   ├──────────────────────→ CANCELLED
                   ├──────────────────────→ EXPIRED
                   └→ PARTIALLY_FILLED ───→ FILLED 或 CANCELLED
SUBMITTED ────────────────────────────────→ REJECTED
`

## 客户端要求

- 在支持时分配唯一的客户端订单 ID。
- 保存服务端返回的订单 ID。
- 消费私有执行事件。
- 重连后通过 REST 回补。
- 将重复投递视为正常情况，按事件或成交 ID 去重。
- 用全部成交之和核对订单成交数量。
- 处理撤单请求进行中同时发生的成交。

## 终态

`FILLED`、`CANCELLED`、`EXPIRED` 和 `REJECTED` 为终态。发生不确定超时后，客户端必须先查询原请求是否成功，不能直接重复下单。

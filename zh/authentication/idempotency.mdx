---
title: "幂等与重试"
description: "在不重复创建订单、提现或结算的前提下重试网络故障。"
---

## 必要行为

对每个支持的写接口发送唯一 `Idempotency-Key`。使用相同 Key 和相同请求体必须返回原结果；相同 Key 搭配不同请求体必须失败。

## 发生不确定超时后

1. 不要立即创建新操作。
2. 通过客户端订单 ID、幂等 Key 或请求 ID 查询。
3. 如果原操作存在，继续追踪。
4. 仅当 API 确认未创建或标记为可重试时才重试。

## 重试类型

| 故障 | 是否重试 |
|---|---|
| 参数验证、权限、保证金不足 | 否；修正请求或账户状态 |
| 限流 | 是；遵循 `Retry-After` 并加入随机抖动 |
| 临时服务故障 | 是；使用有上限的指数退避 |
| 超时后状态未知 | 先查询，禁止盲目重试 |
| 链上最终失败 | 否；修正原因后重新构造并签名交易 |

当团队准备上线自有交易前端并注册自有用户时，需要完成 Builder Onboarding。

## 选择上线方式

| 方式 | 适合对象 | 产品控制力 |
|---|---|---|
| Low-code | 需要以较少定制开发上线品牌前端的团队 | 标准配置 |
| 自定义 SDK/API | 钱包、交易所及构建自定义交易体验的团队 | 完整的前端与接入控制 |

## 创建 Builder 资料

在 Builder Console 中连接由组织控制的钱包，并提交：

- Builder 名称；
- 上线方式；
- 运营与技术联系人；
- 申请开放的产品与网络。

## 获取 Broker ID

激活后，Builder 会获得唯一 Broker ID。将其作为配置保存，并在账户注册、签名消息与 Builder API 请求中保持一致。

## 注册管理员账户

管理员账户用于管理 Builder 设置与手续费配置。必须使用指定管理员钱包，妥善保护签发的 API 凭证，并仅在受保护的后端系统中保存生产凭证。

## 完成标准

Builder 已取得 Builder 资料、Broker ID、管理员账户、确认的上线方式、手续费模型及生产支持联系人后，Onboarding 才算完成。

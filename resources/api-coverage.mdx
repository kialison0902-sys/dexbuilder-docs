<Note>**Status legend:** Published means documented for DexBuilder. `◇` means supported by Orderly but still requires DexBuilder development and is not callable.</Note>

| Status | Capability | Documentation |
|---|---|---|
| Published | Markets, orders, positions, account data, fills, trading fees | Trading Reference |
| ◇ | Account registration and trading-credential management | [Onboard users](/builders/onboard-users) |
| ◇ | Chain and Vault discovery, deposits, withdrawals | [Funds and settlement](/funds/overview) |
| ◇ | PnL settlement and internal transfers | [PnL settlement](/funds/pnl-settlement) |
| ◇ | Builder users, accounts, orders, positions, trades, funding, and liquidation data | [Builder data](/builders/analytics-and-webhooks) |
| ◇ | Default and user-specific Builder fees | [Configure fees](/builders/configure-fees) |
| ◇ | Builder daily volume and fee revenue | [Revenue settlement](/builders/revenue-and-payouts) |
| ◇ | Order tags, referrals, campaigns, and Builder-filtered streams | [Builder data](/builders/analytics-and-webhooks) |

Project CRUD, generic REST Transaction Builder, webhook management, payout creation, and generic analytics endpoints are not in the Orderly REST parity baseline.

DexBuilder exposes dedicated interfaces for user trading and project-level DEX operations.

| Capability | Interface | Primary guide |
|---|---|---|
| Markets, orders, positions, account changes, fills, trading fee | Trading API | [Trading integration](/trading/market-data) |
| Real-time market and private account events | WebSocket API | [WebSocket integration](/trading/websocket) |
| Registration, chains, assets, deposits, withdrawals, PnL settlement | Builder API | [Funds and settlement](/funds/overview) |
| Wallet-ready transaction and typed-message construction | Transaction Builder | [Transaction Builder](/funds/transaction-builder) |
| Projects, user attribution, default and user fees | Builder Admin API | [Build a DEX](/builders/overview) |
| Builder revenue, payouts, analytics, and webhooks | Builder Admin API | [Revenue and payouts](/builders/revenue-and-payouts) |
| TypeScript, Python, React, Postman, and signing tools | SDK and tools | [SDKs and tools](/resources/sdk-and-tools) |

## Environment contract

Every integration must load or receive the configuration for its active environment:

- an environment and base URL;
- authentication and signing rules;
- request and response schemas;
- limits, error codes, and state machines;
- supported chains, assets, and contract addresses.

<Note>
  Products and permissions can vary by project. Use the capabilities returned by your environment and never infer support from another operator's hostname.
</Note>

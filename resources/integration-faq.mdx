## Is Aden the DexBuilder API?

Aden is an operator built on the platform. The DexBuilder Trading Reference intentionally follows Aden's public market and trading API, using the DexBuilder production hostname.

## Can we call Builder endpoints now?

No. Any Builder capability marked `◇` is an Orderly-aligned development requirement, not a published DexBuilder endpoint. Do not append Orderly paths to `api.dexbuilder.com`.

## Which fee endpoint should we use?

Use the current Trading API to read the authenticated user's perpetual trading rate. Builder default fees, user overrides, and daily fee revenue remain `◇` until DexBuilder publishes their contracts.

## Does closing a position settle PnL?

No. Closing realizes PnL. Orderly models PnL settlement as a separate nonce plus signed request, and DexBuilder still needs to implement and publish that flow.

## Is there a generic Transaction Builder or webhook API?

No published DexBuilder contract exists for either. They are not part of the core Orderly Builder REST parity baseline and are not presented as callable APIs.

## What should developers implement today?

Use the published Trading Reference. Use the `◇` pages to plan, estimate, and implement the Builder backlog only after the corresponding DexBuilder contracts become available.

## Is Aden the DexBuilder API?

No. Aden is one operator built on DexBuilder. The public documentation here describes DexBuilder interfaces, and Trading API examples use the DexBuilder production gateway. Project-level onboarding, funds, settlement, fees, revenue, and operations belong to the DexBuilder Builder interface.

## Can we call the Builder endpoints now?

Use the Sandbox or production base URL and credentials issued to your project. If an operation is not enabled for that environment, contact DexBuilder support instead of constructing an undocumented URL.

## Which fee endpoint should we use?

Use the Trading API to read the authenticated user's current perpetual trading rate. Use Builder fee resources for protocol base fees, Builder defaults, user overrides, action quotes, revenue, and payouts.

## Does closing a position settle PnL?

Closing realizes PnL. PnL settlement is a separate account process. Follow the settlement record and ledger rather than inferring settlement from position state.

## May a frontend hold an Admin Key?

No. Builder Admin credentials are server-side secrets. Frontends may use public data, wallet signatures, and narrowly scoped expiring Trading Keys.

## How do we obtain production access?

Complete the [Integration checklist](/getting-started/integration-checklist), test the end-to-end flow in Sandbox when available, and complete the [Go-live guide](/operations/go-live).

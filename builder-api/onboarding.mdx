Use Builder onboarding when your team is preparing to launch its own trading frontend and register its own users.

## Choose a launch path

| Path | Best for | Product control |
|---|---|---|
| Low-code | Teams launching a branded frontend with limited custom development | Standard configuration |
| Custom SDK/API | Wallets, exchanges, and teams building a custom trading experience | Full frontend and integration control |

## Create the Builder profile

Connect the organization-controlled wallet in the Builder Console and provide:

- Builder name;
- launch path;
- operational and technical contacts;
- supported products and networks requested for launch.

## Obtain the Broker ID

After activation, the Builder receives a unique Broker ID. Store it as configuration and use it consistently in account registration, signed messages, and Builder API requests.

## Register the admin account

The admin account manages Builder-level settings and fee configuration. Use the designated admin wallet, protect all issued API credentials, and keep production credentials on secured backend systems.

## Readiness criteria

Onboarding is complete when the Builder has a profile, Broker ID, admin account, approved launch path, fee model, and production support contacts.

---
title: "Request signing"
description: "Sign private Trading API requests and protect credentials."
---

The DexBuilder private Trading API signs a canonical request containing:

1. HTTP method
2. Request path
3. Canonical query string
4. Hex-encoded SHA-512 hash of the request payload
5. Request timestamp

The result is signed with the API secret and sent with the API key and timestamp headers.

## Canonicalization requirements

- Use the exact path sent over the wire.
- Sort and encode query parameters consistently.
- Hash an empty payload for requests without a body.
- Serialize JSON deterministically.
- Use Unix time in the unit required by the endpoint.
- Keep the client clock synchronized.

<Warning>
  Header names and canonical formatting must match the production gateway contract. Use the published SDK or conformance vectors before going live.
</Warning>

## Wallet-signed actions

Registration, withdrawal, and PnL settlement should use a domain-separated wallet message containing the `builder_id`, `chain_id`, nonce, timestamp, and action-specific fields. The Transaction Builder returns the exact message that the wallet must sign.

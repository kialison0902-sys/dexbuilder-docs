## Builder data

Orderly exposes daily volume and leaderboard endpoints plus authenticated `/v1/admin/client/*` resources for attributed-user account, holding, asset, order, position, funding, volume, liquidation, algo-order, and trade data. DexBuilder must publish each endpoint and schema individually.

## Order attribution

Orderly provides `POST /v1/broker/order_enum`, `GET /v1/broker/order_enums`, item read/update operations, and archive/unarchive operations. These are the reference model for DexBuilder order tags.

## Referrals, campaigns, and streams

Orderly also documents multilevel referrals, campaigns, and Builder-filtered WebSocket topics. DexBuilder should publish those only after the permission model and event contracts are implemented.

Webhook configuration and delivery APIs are not part of the Orderly Builder REST parity baseline and have been removed from this documentation.

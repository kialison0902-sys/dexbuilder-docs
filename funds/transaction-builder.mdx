---
title: "◇ Wallet action construction"
description: "Construct Vault calls and EIP-712 messages from published contracts rather than an invented generic REST service."
---

<Warning>DexBuilder has not published a generic Transaction Builder REST API, and Orderly's core Builder model does not require one.</Warning>

The aligned implementation is action-specific:

| Action | Construction model |
|---|---|
| Account registration | Fetch a registration nonce and construct the documented registration message |
| Deposit | Construct token approval and Vault `deposit` calls |
| Withdrawal | Fetch a withdrawal nonce and construct the documented EIP-712 message |
| PnL settlement | Fetch a settlement nonce and construct the documented EIP-712 message |
| Internal transfer | Fetch a transfer nonce and construct the documented signed request |

The connected wallet signs locally. DexBuilder and its SDKs must never receive a raw private key.

If DexBuilder later chooses to offer a server-side payload builder, it needs a separate reviewed contract and must remain marked `◇` until implemented. No `/v1/transactions/build/*` route is documented today.

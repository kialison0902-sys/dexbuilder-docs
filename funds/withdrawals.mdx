## Target sequence

1. read the account's withdrawable balance and supported destination configuration;
2. request a signing nonce from `GET /v1/withdraw_nonce`;
3. construct the exact EIP-712 withdrawal message defined by the published DexBuilder contract;
4. show the user the token, amount, fee, chain, and receiver before signing;
5. submit the signature to the equivalent of `POST /v1/withdraw_request`;
6. reconcile withdrawal records with asset history and destination-chain evidence.

DexBuilder must publish the typed-data domain, field order, nonce lifetime, precision, fee behavior, status values, errors, and retry rules. No guessed withdrawal state machine or quote endpoint is included.

---
title: "Integration checklist"
description: "The implementation and launch checklist for Builders integrating with DexBuilder."
---

## Before development

- [ ] Choose white-label, UI SDK, or direct API integration.
- [ ] Confirm products, chains, collateral assets, regions, and custody model.
- [ ] ◇ Obtain a Sandbox Broker ID and register the admin account.
- [ ] Document your fee model and what the end user will see.
- [ ] Assign owners for wallet, backend, frontend, reconciliation, security, and support.

## Core development

- [ ] ◇ Register the wallet owner under the correct Broker ID.
- [ ] ◇ Create, rotate, expire, and revoke per-user trading credentials.
- [ ] Display contracts, order book, trades, Klines, index, mark price, and funding.
- [ ] Implement order placement, modification, cancellation, and terminal-state tracking.
- [ ] Implement balances, positions, margin, leverage, liquidation, and ADL states.
- [ ] ◇ Implement Vault deposit, signed withdrawal, PnL settlement, and internal transfer from published contracts.
- [ ] ◇ Reconcile daily Builder volume and fee revenue from published history resources.
- [ ] Verify WebSocket reconnect, sequence recovery, and REST backfill.
- [ ] Verify idempotency and retry behavior for every write operation.

## Security and operations

- [ ] ◇ Keep admin-account credentials in a secret manager and backend only.
- [ ] Require wallet signatures for user-authorized asset movements.
- [ ] Configure IP restrictions, scopes, expiration, and key rotation.
- [ ] Handle maintenance and allow users to cancel eligible open orders.
- [ ] Monitor API error rate, stream lag, deposit/withdrawal delay, and reconciliation breaks.
- [ ] Prepare an incident and user-support escalation path.

## Go live

- [ ] Repeat the complete flow in production with a controlled small amount.
- [ ] Verify production contract addresses independently.
- [ ] Confirm actual rate limits and expected traffic.
- [ ] Verify user-facing fee disclosure.
- [ ] ◇ Confirm Builder revenue settlement configuration and daily fee-revenue records.
- [ ] Subscribe to system and maintenance announcements.

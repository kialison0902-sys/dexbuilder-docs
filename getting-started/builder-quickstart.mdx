title: "◇ Builder quickstart"
description: "The Orderly-aligned path from Builder identity to user trading and fee-revenue reporting."
---

<Warning>
  Every Builder operation on this page is a development target. The paths shown are Orderly references, not callable DexBuilder endpoints.
</Warning>

This is the minimum Builder flow DexBuilder should support without inventing a separate project, webhook, payout, or generic transaction-construction API.

<Steps>
  <Step title="◇ Establish the Builder identity">
    Create the Builder profile and obtain the Builder identifier through the administrative onboarding process. Do not assume a separate `project_id` API resource.
  </Step>
  <Step title="◇ Register the user">
    Follow the Orderly pattern: read `GET /v1/registration_nonce`, obtain the wallet signature, and submit `POST /v1/register_account` with Builder attribution.
  </Step>
  <Step title="◇ Create the user's trading credential">
    Add a revocable per-user trading credential, corresponding to Orderly's `POST /v1/orderly_key` flow. Keep Builder administration on the server.
  </Step>
  <Step title="◇ Deposit through the Vault">
    Use the configured collateral token and Vault contract: `approve`, read `getDepositFee`, then call `deposit`. Confirm the account credit through asset history.
  </Step>
  <Step title="Trade with the current API">
    Use the published Trading Reference for markets, orders, positions, fills, account data, and trading fees.
  </Step>
  <Step title="◇ Settle or move funds">
    Implement Orderly-aligned nonce plus signed-request flows for withdrawal, PnL settlement, and internal transfer.
  </Step>
  <Step title="◇ Configure fees and reconcile revenue">
    Implement Builder default and user-level fees, daily volume, Builder information, and daily fee-revenue reporting.
  </Step>
</Steps>

## Core identifiers

| Identifier | Purpose |
|---|---|
| `builder_id` | DexBuilder product name for Builder attribution; final wire naming still requires confirmation |
| `account_id` | Registered user trading account |
| wallet address | User-controlled identity used for registration and wallet-authorized actions |
| trading credential | Revocable credential for authenticated user trading |

See the complete [Builder API alignment](/resources/builder-api-alignment).

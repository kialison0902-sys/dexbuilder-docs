Complete [Builder onboarding](/builder-api/onboarding) before implementing user flows.

<Note>`◇` identifies an operation that is not currently available on DexBuilder.</Note>

## Integration sequence

<Steps>
  <Step title="Register the account">
    `◇ GET /v1/registration_nonce` → sign the registration message containing `brokerId` → `◇ POST /v1/register_account`.
  </Step>
  <Step title="Create an API credential">
    Issue a revocable credential for the registered account and keep the signing secret outside client bundles.
  </Step>
  <Step title="Fund the account">
    Approve the collateral token, read the Vault deposit fee, submit the deposit, and confirm the account balance.
  </Step>
  <Step title="Trade">
    Use the published Trading API for markets, orders, positions, fills, and account data.
  </Step>
  <Step title="Settle and withdraw">
    Use the action-specific nonce and wallet signature required for PnL settlement, internal transfer, or withdrawal.
  </Step>
  <Step title="Operate the Builder">
    Use Builder APIs for user data, fee settings, revenue settlement, order tags, campaigns, and referrals as each interface becomes available.
  </Step>
</Steps>

## Required identifiers

| Identifier | Description |
|---|---|
| Broker ID | Unique identifier assigned to a Builder |
| `account_id` | Unique trading account derived from the wallet address and Broker ID |
| Wallet address | User-controlled address that authorizes registration and asset operations |
| API credential | Revocable credential used for authenticated trading requests |

Continue with [Account registration](/builder-api/account-registration) and [API availability](/builder-api/api-availability).
